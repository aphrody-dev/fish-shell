# fish for the build fleet

Branch `aphrody/fleet` of fish-shell/fish-shell. It is the login shell of ubuntu on n1, n2 and n3,
and of root on n2: `/usr/local/bin/fish`, listed in `/etc/shells`, built by
`build_tools/build_fleet.sh` (copy: `n1:/srv/xbuild/scratch/fish/fish`).

## Login shell for agents and CI

sshd runs every command as `$SHELL -c "<cmd>"`, and agents and scripts send bash.

- **POSIX fallback** (`src/posix_fallback.rs`, called first thing in `src/bin/fish.rs`). Before it reads
  any config, a non-interactive `fish -c` replaces itself with `$FISH_POSIX_SHELL` (default
  `/bin/bash`), passing the same string, environment, working directory and `$1…`. It does this when the string:
  - does not parse as fish or fails fish's syntax checks (`do … done`, `${x#y}`, `$?`, heredocs,
    `case … esac`, `f() { … }`, `$((…))`);
  - calls a command only POSIX shells have (`[[`, `local`, `declare`, `unset`, …);
  - uses bash's `set` options (`set -euo pipefail`, `set +x`);
  - or has an unquoted `*` and bash parses it. fish fails a command whose wildcard matches
    nothing, where bash passes the word on, so `rm -f *.tmp && …` would stop.

  Everything else runs natively in fish. Interactive sessions never fall back.
  `FISH_POSIX_FALLBACK=0` turns it off, and `FISH_POSIX_FALLBACK=always` sends every `-c` string to bash.
  A string handed to bash costs one more exec: 6.6 ms instead of 3.5 ms for a loop on n2.
- **Non-interactive sessions write nothing**:
  - no history, as upstream;
  - no universal variables: they are read, but `set -U` stays in the session unless `FISH_SAVE_UVARS=1`;
  - no warnings about unusable data, config or cache dirs (only interactive sessions complain).
  Greeting, prompt and theme are interactive-only upstream already. `fish --profile-startup -c true` runs none of them.
- **`/etc/fish/conf.d`** on every host:
  - `aphrody-agent.fish` (from `etc/fleet/conf.d/`): when the session is not interactive and stdout is not a
    terminal, `set_color` prints nothing.
  - `flatpak.fish` (from `etc/fleet/conf.d/`): replaces the vendor file of the same name, which runs
    `flatpak --installations` (~48 ms) at every start. It sources the vendor file only in interactive sessions.
  - `aphrody-env.fish`: generated by `bun run fleet fish-env` (agentkit `scripts/fleet.ts`). It holds the
    variables that `/etc/environment`, `/etc/profile.d/aphrody-*.sh` and `*uutils*.sh` set, as bash
    evaluates them. PATH entries are prepended unless already on PATH, so uutils comes first on n2. Regenerate it
    after changing a source.
- Not covered: `ssh host < script.sh` with no command, where fish reads stdin as fish. Use
  `ssh host bash -s < script.sh`; none of our tools sends a bare script.
- Strings that are valid in both shells still run in fish. Of 29 typical one-liners, 27 behave
  identically. The other two differ only in wording: `time` (fish's report format) and the
  message for an unknown command.

### Verified after chsh (fresh ssh connections, before/after diff)

Checked for ubuntu@n1, ubuntu@n3, root@n2 and `su ubuntu` on n2:
- bash one-liners (loops, `${y#z}`, heredoc, `[[ ]]`, `$?`, `case`, `set -euo pipefail`, arrays, `local`)
  produce the same output and exit codes;
- `true` prints nothing; colour; exit codes; stdin;
- rsync both ways; scp (sftp and `-O`); git ls-remote and push over ssh;
- `sudo -n`; labs `scripts/remote.ts`-style commands; agentkit `bun run fleet …`, which goes through `sudo bun run -`;
- a `User=ubuntu` systemd unit gets `SHELL=/usr/local/bin/fish` and `$SHELL -c` works both ways;
- the GitHub runners stay active (n1 runs them as ubuntu, n2 as builduser, and their steps call bash explicitly),
  and so does nomad on n2 (it runs as root and executes tasks directly).

Interactive logins start fish (`status is-login`).

Differences, all in commands that run natively in fish:
- they get the profile.d environment, which bash `-c` never read. On n2 that means
  `RUSTUP_HOME`/`CARGO_HOME=/srv/toolchain/*` (nightly by default) instead of `/opt/rust/*` (stable 1.100),
  and `CARGO_TARGET_DIR=/srv/build/target-shared`;
- on n1, bun, cargo and sccache resolve through `/srv/toolchain/bin` (the same versions);
- strings that fall back to bash keep bash's environment, from `~/.bashrc`;
- `su ubuntu -c '<fish string>'` from `/root` prints "Unable to open the current working directory", where bash prints nothing.

ControlMaster connections that were already open keep the old shell until they reconnect.

## Changes

- **Bare POSIX assignments.** A job that is only `VAR=value` words runs like `set VAR value`
  without scope options: an existing variable is updated in its own scope and keeps its export
  flag, and a new one is local to the function, or global at top level. Words run left to right: `G="x"; $G`, `a=1 b=$a`, `x=$(cmd) && ...` and `a=` work. `$status` is that of the last
  command substitution, or 0. It is still an error in a pipeline (`: | a=b`), after
  `not`, or with a redirection, as before. Not upstream: fish has always refused it
  (#8359, #9760). Code: `src/ast.rs` (the parser accepts it only at the head of a job),
  `src/parse_execution.rs` (`run_bare_assignments`), `src/parse_util.rs` (a `(cmd)` in the
  value is not a command substitution in command position). Tests: `tests/checks/variable-assignment.fish`,
  `tests/checks/invocation.fish`, `src/parser.rs`.
- **Lean build.** `[profile.fleet]` (release + one codegen unit + `panic=abort`; the panic
  hook still runs) and `build_tools/build_fleet.sh`: no default features (no man pages,
  which need sphinx, and no message catalogs), `-C target-cpu=x86-64-v3` (n1, n2 and n3 support it),
  and `-C relocation-model=static`, which builds a non-PIE executable. The loader then applies
  223 relocations instead of 12674 (44008 with message catalogs), and that is where the
  startup time goes.
- **Upstream PRs taken:**
  - #13100 `history: mark map_file unsafe`: makes a safety requirement explicit, and the code is unchanged.
  - #13033 `Prefer HOME when initializing PWD`: ssh starts fish without `PWD`. When HOME is a
    symlink, `$PWD` is now `~` instead of the physical path.
  - #13105 `fish_default_mode_prompt: printf instead of echo`: trivial.

## Rejected

- #12970 function path cache: the reviewer says it skips IO it needs, and the PR is unfinished.
- #12741 `--no-config` without private mode: changes behavior, has no review, and the fleet does not need it.
- #12008 retry writes on EINTR: the author abandoned it. #12069 ENAMETOOLONG: open review issues.
- #13061 tinyexpr rewrite, #10840 removal of IFS, #12095 and #12939 (large interactive features):
  too big or risky, and they do nothing for non-interactive `-c`.
- Active forks: none is ahead of upstream with anything relevant. faho has 1 commit (zigbuild static
  build), Berrysoft has Cygwin work, and the others are 0 ahead.
- Not reading config when not interactive (#5394): this would break the PATH setup that ssh
  one-liners rely on.

## Startup (hyperfine -N, 50 warmup, 1000 runs, empty HOME)

n1 (12c, load 50-100 from other jobs during the run, so expect noise). Means in ms:

| fish -c          | upstream release | fleet profile, PIE | fleet (non-PIE) | fleet, no l10n, non-PIE (deployed) |
|------------------|-----------------:|-------------------:|----------------:|-----------------------------------:|
| `--no-config true` | 2.5 | 2.8 | 1.7 | **1.6** |
| `true` (fish config only) | 4.7 | 3.9 | 3.2 | **3.2** |
| one-liner loop   | 10.9 | 11.8 | 10.1 | 11.7 |
| `true` with host vendor_conf.d | 27.4 | 26.2 | 25.3 | **22.7** |

n2 (8c, CachyOS, load ~3), `--no-config -c true`: system fish 4.9.3 is 4.6 ms, upstream 4.5 ms, deployed 3.3 ms.

The profile alone (LTO is already in upstream's release profile, plus one codegen unit, abort and v3)
is within noise. The non-PIE link is a consistent 1.3-1.5x on bare startup.
On a real host most of the time is in the distro's `vendor_conf.d`. On n1,
`flatpak.fish` runs `flatpak --installations` at every start, which takes ~48 of ~50 ms in
`fish --profile-startup`. To fix that, guard it with `status is-interactive`, or remove it on fleet hosts.
